# Releasing KCleaner

## Version 1.0.0 publication

The initial GitHub release distributes Engagetal's supplied `KCleaner-1.0.dmg` unchanged. Its embedded app version is expected to be 1.0; the repository tag is v1.0.0. The repository adds MIT licensing, documentation, and a download-count utility. The binary has not been rebuilt from this publication commit, and binary/source reproducibility, Developer ID signing, and notarization are not asserted.

The release includes `LICENSE` and `SHA256SUMS.txt`. Retain the MIT notice when redistributing the app. The source ZIP generated by GitHub contains the complete repository at the tag; the main-branch ZIP can include later changes.

## Future releases

1. Update `CFBundleShortVersionString` and `CFBundleVersion` in `Info.plist` and add release notes.
2. Compile with `bash build.sh` and complete the manual validation in `CONTRIBUTING.md`.
3. Prepare a distribution copy. Remove the local `KCSourceFolder` value from its Info.plist before signing, so a public binary does not contain a developer's source-folder path. Include the MIT LICENSE in the app resources and DMG.
4. Sign using the company's Developer ID certificate, notarize with Apple's tools, and staple the notarization ticket. Keep certificates and credentials out of the repository.
5. Create a DMG with the app, Applications shortcut, and LICENSE. Verify the image and test installation on a separate Mac.
6. Create a new version tag and GitHub Release. Upload the DMG and SHA-256 checksum file. GitHub automatically provides the tagged source ZIP and tar.gz.
7. Check public asset metadata and download counts through the API. Avoid downloading the DMG just to check its URL, since doing so can increment the count.

## Counting accurately

`python3 download-count.py` fetches all published releases and paginates each release's assets. It sums only asset names ending in `.dmg`, case-insensitively, and displays integer counts without rounding. It fails instead of presenting a partial total if an API call fails.

GitHub is the source of truth for these counters; API responses may have normal service delays. The total is a snapshot collected across requests, not an atomic transaction. Counts do not identify unique people, successful installations, or downloads outside GitHub. Keep old release assets to preserve their counts.

For the current release alone:

```sh
curl -fsSL https://api.github.com/repos/engagetal/KCleaner/releases/tags/v1.0.0
```

Find `KCleaner-1.0.dmg` under `assets` and inspect `download_count`. Read-only API requests do not download the DMG. Public unauthenticated API requests are rate limited. The script accepts an optional `GITHUB_TOKEN` environment variable for authenticated read access; never commit a token.

GitHub API documentation: https://docs.github.com/en/rest/releases/assets
